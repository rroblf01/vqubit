# Serialización

vqubit puede guardar y recuperar circuitos como texto, y exportarlos a
OpenQASM 2.0.

## JSON

Cada valor serializable se convierte en un objeto JSON con un campo
`cirq_type`, y `read_json` lo reconstruye.

```python
import vqubit as vq

q0, q1 = vq.LineQubit.range(2)
circuito = vq.Circuit(vq.H(q0), vq.CNOT(q0, q1), vq.Rz(0.3)(q1))

texto = vq.to_json(circuito)
recuperado = vq.read_json(texto)
print(recuperado == circuito)   # True
```

También hay variantes comprimidas:

```python
import vqubit as vq

circuito = vq.Circuit(vq.H(vq.LineQubit(0)))
datos = vq.to_json_gzip(circuito)          # bytes comprimidos
assert vq.read_json_gzip(datos) == circuito
```

Puedes consultar el tipo de un valor y buscar la clase por su nombre:

```python
import vqubit as vq

print(vq.json_cirq_type(vq.X))             # 'XPowGate'
print(vq.cirq_type_from_json('LineQubit')) # <class 'vqubit._qubits.LineQubit'>
```

## OpenQASM 2.0

```python
import vqubit as vq

q0, q1 = vq.LineQubit.range(2)
circuito = vq.Circuit(vq.H(q0), vq.CNOT(q0, q1), vq.measure(q0, q1, key="m"))
print(vq.qasm(circuito))
```

Produce:

```qasm
// Generated by vqubit
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
creg m[2];
h q[0];
cx q[0],q[1];
measure q[0] -> m[0];
measure q[1] -> m[1];
```

Las puertas sin instrucción nativa (como la de Fredkin) se expanden con su
descomposición antes de escribirse. La clave de medida es el registro clásico,
tal cual, para que el texto se pueda volver a leer con la misma clave.

Y se lee con `circuit_from_qasm`, que es un analizador propio (sin `ply` ni
ninguna otra dependencia):

```python
import vqubit as vq

circuito = vq.circuit_from_qasm("""
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
creg c[2];
h q[0];
cx q[0],q[1];
measure q[0] -> c[0];
measure q[1] -> c[1];
""")

print([(type(op.gate).__name__, op.qubits) for op in circuito.all_operations()])
assert vq.qasm(circuito) == vq.qasm(vq.circuit_from_qasm(vq.qasm(circuito)))
```

Entiende el juego de puertas de `qelib1` (`u3`, `u2`, `u1`, `x`…`tdg`, `sx`,
`rx`/`ry`/`rz`, `cx`/`cz`/`cy`/`ch`/`swap`/`ccx`, sus formas controladas),
expresiones con `pi`, definiciones `gate` propias (que expande en línea),
medidas, `reset`, `barrier` y las condicionales `if(c==N)`. Un programa mal
formado lanza `vq.QasmParseError` con el número de línea.

## Quirk

`quirk_url` convierte un circuito en un enlace al simulador
[Quirk](https://algassert.com/quirk), para las puertas que Quirk entiende de
forma nativa:

```python
import vqubit as vq

q0, q1 = vq.LineQubit.range(2)
circuito = vq.Circuit(vq.H(q0), vq.CNOT(q0, q1))
print(vq.quirk_url(circuito))   # https://algassert.com/quirk#circuit=...
```

Quirk escribe las rotaciones como potencias (`X^t`, con `t = rads/π`), así que
`Rx`/`Ry`/`Rz` van y vuelven con esa forma, y una medida va como `Measure` con
la clave `m`. La ida y vuelta conserva la unitaria de todo lo que Quirk sabe
representar; una puerta que no (por ejemplo `iSWAP`) lanza `TypeError`.

El objeto `QasmArgs` transporta el contexto (nombres de qubits, precisión y
argumentos libres) que recibe el escritor QASM de una puerta.

## El contrato de `numpy` y `sympy`

vqubit no depende de `numpy`, pero lo usa cuando está instalado, y ese contrato
es estable:

- **Entrada**: `state_vector=`, `density_matrix=`, matrices para `MatrixGate` y
  `unitary=`, y parámetros en general aceptan tanto listas de Python como
  arrays de `numpy`.
- **Salida**: si `numpy` está instalado, `state_vector()`,
  `density_matrix()`, `final_state_vector`, `density_matrix_of()`, `unitary()`
  y las matrices de los canales son arrays de `numpy` con `dtype`
  `complex128`; sin `numpy` son listas anidadas de `complex` y el resto de la
  API no cambia.
- **Simbólico**: los parámetros son `vq.Parameter` (o `vq.symbol("t")`), no
  `sympy.Symbol`: un símbolo de `sympy` **no** se acepta en una puerta (falla
  con `TypeError`, en vez de convertirlo en silencio). Un `sympy.Symbol` sí
  vale como clave de un `vq.ParamResolver`, porque se reduce a su nombre.
